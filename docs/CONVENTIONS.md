# 数据与写作规范

本文件解释"为什么这样写"，字段的机器可读定义在 [`config/schema.json`](../config/schema.json)。

## 1. 唯一事实源

`data/*.json` 是内容的唯一来源，`README.md` 是 `scripts/build.py` 的产物。

- 改内容 → 改 `data/`，然后 `python3 scripts/build.py`
- 直接改 README → 下次生成会被覆盖，`--check` 会报错
- 这也是本项目"机可用"的基础：JSON 可被程序、Agent、检索服务直接消费

## 2. 主题与文件

- 一个主题一个文件：`data/<category-id>.json`，内容是**条目数组**
- 主题的标题、描述、顺序只写在 `config/categories.json`，数据文件里不重复
- 新增主题：在 `config/categories.json` 追加一项，再新建同名文件；顺序即 README 中的顺序

## 3. 字段速查

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 全局唯一 slug，小写连字符。**创建后不再修改**，外部引用依赖它 |
| `name` | ✅ | 展示名，保留官方大小写 |
| `url` | ✅ | 主入口，必须 `http(s)`，不要带追踪参数的短链 |
| `desc` | ✅ | 一句话中文简介，6–60 字 |
| `tags` | ⬜ | 1–3 个细分标签，只能取受控词表；没有合适的就不填 |
| `pricing` | ✅ | `free` / `freemium` / `paid` / `open-source` |
| `status` | ✅ | `active` / `beta` / `deprecated` / `archived` |
| `added` | ✅ | 收录日期 `YYYY-MM-DD` |
| `vendor` | ⬜ | 归属机构，未知就省略 |
| `lang` | ⬜ | `zh` / `multi` / `en`，默认 `zh` |
| `featured` | ⬜ | 置顶，每个主题最多 3 条 |
| `links` | ⬜ | `{repo, docs}`，仅在入口不唯一时填 |

## 4. 写作口吻

- 一句话说清"是什么 + 凭什么值得收"，不用第二句
- 陈述句，不加句号、不感叹
- 禁用营销词：最强、颠覆、革命性、一站式、神器
- 不要重复名称开头（❌ `LangChain 是一个 LLM 编排框架` → ✅ `LLM 应用编排框架，插件生态完整`）
- 60 字上限是硬约束，用于保证 README 扫读效率

## 5. 顺序

**文件里的顺序就是 README 里的顺序**，生成器不排序。想调位置，直接移动 JSON 数组里的对象。

- 按"知名度 / 上手难度 / 与中文用户的贴合度"人工编排，不追字母序
- `featured` 只加 ⭐ 标记做强调，**不改变位置**；每个主题最多 3 条
- 新增条目默认追加到末尾，再手动挪到合适位置
- 顺序变了但内容没变，`--check` 依然会失败——这是对的，说明 README 该重新生成了

## 6. 标签

标签只回答一个问题：**"这个项目有什么是别的字段推不出来的特点？"**

受控词表（12 个，硬校验，词表定义在 `config/schema.json`）：

```
国产 多模态 语音 图像 视频 代码
知识库 工作流 私有化 企业 协议 评测
```

规则：

- 1–3 个，宁少勿滥；填不出合适的就整条不填（`tags` 可省略）
- **不要**写 `API` `网页版` `开源` `免费` `付费` `平台` `模型` 这类词——它们要么能从 `pricing` / `lang` / 所属主题推出，要么是占位词
- 同一主题内人人都具备的能力也不打标签（03 全是编程工具，就不必给每条打 `代码`）
- 双字标签只表达"能力/形态/归属"，不表达评价（禁止 `好用` `推荐`）
- 新增标签必须改 `config/schema.json` 的枚举，会出现在 PR diff 里，方便讨论要不要收录

对照：

| 项目 | ❌ 旧写法 | ✅ 新写法 | 理由 |
|---|---|---|---|
| DeepSeek | `国产` `API` `开源` | `国产` `代码` | API 人人都有；开源已由 `pricing` 表达 |
| MiniMax | `国产` `多模态` `语音` | `国产` `语音` `视频` | 语音/视频是它真正的差异点 |
| Llama | `开源` `模型` | （不填） | 开放权重已写进 `desc` 和 `pricing` |

## 7. 状态与维护

- `active` / `beta` 会出现在 README
- `deprecated` / `archived` 保留在 JSON 里（机器仍需读取历史），但**不展示**
- 超过 12 个月无更新的项目，标记为 `archived` 而不是直接删除

## 8. 提交前自检

```bash
python3 scripts/validate.py        # 规范校验
python3 scripts/build.py --check   # README 是否与数据一致
```

两条都过再提交。

## 9. 常见校验报错对照

| 报错 | 原因 |
|---|---|
| `未知字段 'star'` | 字段名拼错，或想加新字段——先改 schema |
| `id 全局重复` | 两个主题收了同一个项目，只保留一个 |
| `链接重复` | 同一入口被收录两次（自动忽略尾部斜杠） |
| `长度超限` | `desc` > 60 字，`name` > 40 字，`tags` > 3 个 |
| `取值非法` | `pricing` / `status` / `lang` 不在枚举内，或 `tags` 用了词表外的词 |
| `缺少必填字段` | 漏了 `id` / `desc` / `url` 这类必填项 |
