# 流程：结构性变更管理

## 目的

结构性改动（schema 字段、标签词表、主题结构、框架层脚本）影响所有下游数据与消费方，必须先论证、留痕（ADR）、再实施。`/plan` 指令是本流程的入口。

## 触发

- 用户/维护者想改 `config/schema.json`、`config/tags.json`、`config/categories.json`、`scripts/*.ts`、`tests/`、`.github/`
- `contribution-review` 分诊出结构性 PR
- Agent 在执行中发现规范矛盾（如文档与 schema 不同步）

## 输入

改动意图（一句话）+ 触发原因。

## 角色

- **维护 Agent**：评估影响面、起草 ADR、实施
- **维护者**：批准 ADR、合并

## 步骤

### 1. 分类与影响评估

| 改动类型                  | 破坏性            | 评估重点                                                             |
| ------------------------- | ----------------- | -------------------------------------------------------------------- |
| schema 新增可选字段       | 否                | 消费方兼容；是否与现有字段语义重叠                                   |
| schema 改必填/枚举/删字段 | **是**            | 全量现有数据回放（改后跑 `npm run validate` 找违规）；下游消费方公告 |
| tags 词表增词             | 否                | 是否与现有词重叠、是否违反「别的字段推不出来」原则                   |
| tags 词表删词             | **是**            | 全量扫描使用该词的条目，给出迁移方案                                 |
| categories 增删/改序      | 增删否 / 改 id 是 | id 永不改；删除主题须迁移条目                                        |
| scripts 框架层改动        | 视情况            | 属母版职责：派生仓库不直接改，回母版提 PR                            |

### 2. 写 ADR

按模板落 `.agents/references/adr/NNNN-<slug>.md`（编号递增，创建后不改不删；推翻旧决策用新 ADR 引用旧 ADR）。模板字段：**背景 / 决策 / 后果 / 替代方案**。

### 3. 计划确认

用 `/plan` 的输出格式给维护者：动机、改动文件、影响面、自检方式、回滚方式。**等确认**。

### 4. 实施

- 一个 PR 一件事；PR 描述用 `templates/pr-structural.md`（含 ADR 链接）
- 数据层破坏性变更：同一 PR 内完成全量数据迁移
- 跑 `npm run check`（框架层改动加 `npm test`）

### 5. 公告

合并后：更新 `docs/CONVENTIONS.md` 相应章节；消费方可见的变更在 PR 描述里写迁移指引。

## 输出

ADR + 结构性 PR + 文档同步。

## 异常

| 情况                   | 处置                                                      |
| ---------------------- | --------------------------------------------------------- |
| 发现文档与 schema 矛盾 | 停下，写 ADR 说明矛盾与建议方向，交维护者裁决——不自行选边 |
| 紧急修复（CI 全红）    | 先最小修复 + 事后补 ADR（48 小时内）                      |
| 维护者否决             | ADR 标记 `status: rejected` 保留存档                      |

## 红线

- 无 ADR 的结构性 PR 在 `contribution-review` 中应被要求补
- Agent 不改现有条目/主题的 `id`，不改 `additionalProperties` 去给坏数据放行
- ADR 编号不重用、文件不改写（修订 = 新 ADR）
