# 流程：issue 分诊

## 目的

把仓库三类 issue（推荐条目 / 失效链接 / link-check 巡检）在分诊后转成可执行动作：PR、流程移交或标准回复。

## 触发

新 issue 打开（人工创建或 CI 自动创建）。

## 输入

issue 标题、正文、label。仓库的 issue 模板：

- `推荐一个条目`（`.github/ISSUE_TEMPLATE/add-entry.yml`）：名称 + 链接 + 建议主题 + 一句话简介
- `报告失效链接`（`.github/ISSUE_TEMPLATE/broken-link.yml`）：条目名 + 原链接 + 现象
- CI 自动：`链接巡检失败 <日期>` + `link-check` label（来自 `links.yml`）

## 角色

- **分诊 Agent**：判定类型、代提 PR 或移交流程、评论回复
- **维护者**：确认收录、关闭 issue

## 步骤

### 1. 分诊表

| 类型                      | 动作                                                                               |
| ------------------------- | ---------------------------------------------------------------------------------- |
| `[条目]` 推荐             | 走第 2 步（→ add-entry 技能）                                                      |
| `[失效]` 报告             | 走第 3 步（→ check-links 死链口径）                                                |
| `link-check` label（CI）  | 移交 `ci-incident-response` 流程；若判定为真实死链波及面，转入 `weekly-link-audit` |
| 其他（无模板/跑题/ spam） | 跑题：友好重定向到对应模板；spam：报告维护者，不删不吵                             |

### 2. `[条目]` 推荐处理

1. 按 `add-entry` 技能起草条目，走 `review-entry` 技能的四段清单自审
2. 通过 → Agent 在分支上开 PR（引用 issue 编号），评论回复（用 `templates/issue-replies.md` 的收录话术 + PR 链接）
3. 有问题（不满足收录标准/信息不足）→ 评论说明缺什么 + 可照抄的修正 JSON；**不承诺收录**（合并是维护者的事）
4. PR 合并后提醒维护者关闭 issue

### 3. `[失效]` 报告处理

1. 与 `config/link-status.json` 交叉核对：该条目是否已在观察名单/已知不可达
2. 核实现象：本机打开原链接复现一次（海外视角）
3. 按死链处置口径（`check-links` 技能）：URL 变了 → 代提修正 PR（`fix: 修正 <名称> 官网域名`）；项目停维 → 提 `archived` PR；单次失败无法确认 → 评论说明进入观察名单，一周后 `weekly-link-audit` 跟进
4. PR 合并后提醒维护者关闭 issue

## 输出

- issue 评论（三态：已代提 PR / 需补充信息 / 已移交流程）
- 关联 PR

## 异常

| 情况                      | 处置                                            |
| ------------------------- | ----------------------------------------------- |
| 信息不足（无链接/无名称） | 用追问话术请补充；7 天无响应建议维护者关闭      |
| 推荐条目不满足收录标准    | 用拒绝话术引用 `CONTRIBUTING.md` 标准，给出原因 |
| 与现有条目重复            | 指出现有条目位置，建议关闭                      |
| 推荐条目主题归属不明      | 在 issue 里问推荐人，不猜                       |

## 红线

- 不承诺收录——「代提 PR」≠「会被合并」
- Agent 不关闭 issue（关闭是维护者的动作）
- 不在 issue 里与推荐人争论；只引用标准
- 每个 issue 至少要有一条署名「由 Agent 处理」的评论，保证可审计
