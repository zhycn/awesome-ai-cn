# /plan

用户想做结构性改动：加主题、调标签词表、改 schema、改生成逻辑。这类改动影响面大，**先规划确认，再执行**。

## 步骤

1. **读全上下文**：`docs/CONVENTIONS.md`、`config/schema.json`、相关 `scripts/*.ts`
2. **明确改动类型与影响面**：
   - 新主题 → 走 `new-category` 技能的必要性检查
   - 标签词表 → 评估对现有条目的追溯影响（新词表是否让旧标签失效）
   - schema 字段 → 兼容性（新增可选字段安全；改必填/枚举会破坏现有数据和消费方）
3. **产出一份简短计划**：动机、改动文件清单、对现有数据的影响、回滚方式
4. **等用户确认**再动手；执行时一个 PR 一件事

## 输出格式

```
## 改动计划：<一句话>

**动机**：…
**改动文件**：…
**影响面**：…
**自检方式**：npm run check
**回滚**：revert 单个提交即可
```
