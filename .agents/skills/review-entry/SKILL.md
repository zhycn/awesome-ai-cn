# 审阅一条条目改动

## 输入

一个 PR 的 diff（或用户描述的改动意图）：新增 / 修正 / 状态变更 / 主题调整。

## 审阅清单

按顺序逐项核对，每项给 ✅ / ❌ / ⚠️ 并附理由。

### 1. 收录标准（`CONTRIBUTING.md`）

- [ ] 入口明确、稳定、可直达，非营销页、非 API 中转/倒卖 token 站点
- [ ] 仍在维护（12 个月内有更新）
- [ ] 未与其他主题重复收录
- [ ] 需科学上网的已标 `"access": "proxy"`

### 2. 字段合规（以 `npm run validate` 为准）

- [ ] 必填字段齐全；无 schema 外字段
- [ ] `id` 唯一、小写连字符、语义稳定
- [ ] `desc` 6–60 字，陈述句，无句号，无营销词，不以名称开头
- [ ] `tags` 只用 `config/tags.json` 词表，≤3 个，无冗余标签
- [ ] `pricing` / `status` / `lang` 在枚举内
- [ ] `added` 是当天日期

### 3. 结构纪律

- [ ] 新条目在主题文件**末尾**
- [ ] 只动了该动的内容（一个 PR 一件事；顺带的重排/改格式应要求拆分）
- [ ] `featured` 每主题不超过 3 条

### 4. 产物一致性

```bash
npm run check
```

- [ ] validate / build:check / format:check / typecheck / test 全过
- [ ] PR 标题符合 Conventional Commits（CI 会校验）

## 输出格式

```
## 审阅结论：通过 / 需修改 / 拒绝

**收录标准**：…
**字段合规**：…
**结构纪律**：…
**产物一致性**：…

**需要修改的点**（按优先级）：
1. …
```

## 判定口径

- **拒绝**：不满足收录标准（停维、重复、营销页、中转站）
- **需修改**：标准满足但有字段/写作/顺序问题——给出可直接照抄的修正 JSON
- **通过**：全部 ✅，可合并；提醒维护者合并后按知名度调整条目位置
