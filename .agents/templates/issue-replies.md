# issue 标准回复话术

> Agent 回复 issue 时从这里取话术，按需微调但保持结构与口吻；每条回复附「——由 Agent 处理」署名。不在此列的情况按最接近的模板改写，不即兴长篇。

## 推荐条目 → 已代提 PR

```
感谢推荐。已按 <主题> 主题起草条目并代提 PR #<编号>，请留意审阅进度。
收录与否以 PR 合并为准——由 Agent 处理
```

## 推荐条目 → 需要补充信息

```
感谢推荐。还差一点信息才能起草：

- <缺什么：稳定入口链接 / 一句话简介 / 建议主题……>

补充后我会继续处理；7 天内未回复将建议关闭本 issue。——由 Agent 处理
```

## 推荐条目 → 不满足收录标准（拒绝）

```
感谢推荐。对照 [收录标准](../../CONTRIBUTING.md)，本次暂不收录，原因：

- <引用具体条款，如：项目 12 个月内无更新 / 入口为营销页 / 与现有条目 X 重复>

欢迎在条件变化后重新推荐。——由 Agent 处理
```

## 失效链接 → 已核实并处理

```
已核实：<现象一句话>。按死链处置口径 <更新了链接 / 转为 archived>，PR #<编号>。
——由 Agent 处理
```

## 失效链接 → 暂无法确认（进入观察）

```
已核实一次，暂无法下结论（暂态失败常见）。该条目已进入观察名单，下周一链接巡检会跟进；连续两周不可达将按死链处置。——由 Agent 处理
```

## link-check issue → 误报判定

```
本轮失败率 <N>%，判定为 <网络/巡检器故障>，结果作废，不做任何条目改动。下个周期自动复检。——由 Agent 处理
```

## link-check issue → 转入处置

```
本轮失败 <N> 条，含真实死链，转入每周链接巡检流程处置，结果见后续 PR。——由 Agent 处理
```

## 跑题 issue → 重定向

```
这个问题更像 <条目推荐 / 失效报告 / 安全问题>。为便于处理，建议用对应 issue 模板重开：<链接>。——由 Agent 处理
```
